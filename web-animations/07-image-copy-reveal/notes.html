What it is

An image and a block of copy arrive one after the other: the image first, then the headline, subhead and body in a short stagger. Every timing in it is exposed in Parameters, so you can find the version that feels settled rather than busy.

Where it comes from

Nowhere in particular. It's the most common entrance on the web, built here on the browser's own Web Animations API instead of a library. Each piece gets one animation on a shared timeline, which is what makes the scrub bar and the scroll-driven mode possible.

Support and failure mode

Behaves the same in Firefox, Chrome and Safari's engine (tested October 2026). With JavaScript off, the page shows the finished layout. With reduced motion on, everything simply fades in quickly. The balanced headline wrapping is a nicety that older browsers ignore.

When I'd use it. When I wouldn't.

On a page that has one idea worth slowing down for, like a product hero or the opening of a case study. The pause before it starts matters more than the curve. I wouldn't put it on every section of a long page: by the third reveal it's a toll, not a moment, and anyone reading quickly ends up waiting on copy that was ready all along.

Implementation notes

Line-by-line splitting measures where the browser actually wrapped the text, so it waits for the web fonts before measuring. Delays set the order; nothing chains on callbacks. "When scrolled into view" holds the scroll for a moment once it fires, which is worth turning off anywhere people scroll to read.
